# Local Masking Tool

画像内の顔やナンバープレート候補を検知し、ブラウザ上で範囲を修正してぼかし済み画像を書き出すローカルファーストの試作ツールです。

## 実行

ローカルの顔検知APIまで使う場合:

```bash
python3 server.py
```

ブラウザで `http://127.0.0.1:5173` を開きます。

クラウド公開版は静的Webアプリとして動きます。画像の読み込み、顔検知、ナンバープレート候補検知、手動範囲編集、JPEG/PNG書き出しはブラウザ内で動きます。

顔検知はMediaPipe TasksのWASMモデルをブラウザで読み込んで実行します。写真データはクラウドAPIへ送信しません。初回だけ、ブラウザがMediaPipeのJavaScript/WASM/モデルファイルをCDNから取得します。

## 現状

- 画像はブラウザ内のCanvasで処理されます。
- クラウドへのアップロード処理はありません。
- 顔検知はブラウザ内のMediaPipe Tasksをまず試し、失敗した場合はブラウザの `FaceDetector` API を試します。ローカル実行時のみ、最後のフォールバックとして `server.py` 経由でmacOS標準のVisionフレームワークを使います。
- `server.py` の顔検知APIは `127.0.0.1` で動くローカルサーバーです。画像は一時ファイルとして処理後すぐ削除されます。
- ブラウザ内顔検知とローカル顔検知は画像全体ではなく、分割タイルを拡大して検知します。広い写真内の小さい顔を拾いやすくするためです。
- ナンバープレート検知はローカルのエッジ解析による候補検出です。実運用では検出漏れと誤検出を前提に、手動修正で補います。
- 対象範囲はドラッグ移動、右下ハンドルでリサイズ、Deleteキーまたは削除ボタンで削除できます。
- 書き出しはJPEGまたはPNGを選べます。元画像がJPEGの場合、PNGで書き出すと可逆圧縮になるためファイルサイズが大きくなりやすいです。

## GitHub Pages

`.github/workflows/pages.yml` を追加しています。GitHubリポジトリのPagesをGitHub Actionsに設定して `main` にpushすると、静的版がGitHub Pagesへ公開されます。

ローカルの `server.py` と `tools/detect_faces.swift` はmacOS向けのローカル顔検知用です。GitHub Pages上では実行されません。

## プライバシー

- 写真データはCanvas上で処理されます。
- クラウド公開版では、顔検知のために写真をサーバーへアップロードしません。
- MediaPipe Tasksの公式説明では、入力データは端末上で処理され、Googleサーバーへ送信されません。
- MediaPipe Tasksは利用状況や性能に関するメトリクスをGoogleへ送信する可能性があります。写真そのものではありませんが、公開利用する場合は必要に応じて利用者へ明示してください。

## 将来の拡張方針

ローカル検知精度を上げる場合は、以下のどちらかが現実的です。

1. ブラウザ内WASM/ONNX
   - YOLO系などの軽量モデルをONNX Runtime Webで実行します。
   - 画像はブラウザ外に出ません。
   - モデルファイルの配布サイズと端末性能が制約になります。

2. ローカルバックエンド
   - ブラウザUI + localhost上のPython/FastAPIでOpenCVやONNXを実行します。
   - 精度と実装自由度は上がります。
   - 利用者端末へのランタイム配布が必要になります。

クラウド検知を併用する場合は、原本画像を直接保存しない設計、短期署名URL、即時削除、暗号化、監査ログ、リージョン固定、処理後の明示削除を最低条件にしてください。最終的なぼかし編集と書き出しはブラウザ側に残すと、クラウドに置く情報を最小化できます。
